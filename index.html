RETRIEVAL OPTIMIZATION 慧咨环球 · 海关业务

DeepRAG 海关知识检索深度优化引擎

技术关键词RAG · Dense / Sparse · RRF · Rerank · Query 理解

针对基础 RAG 在跨地区规则、长文档和专业术语上的召回不足，开展独立检索优化专项，在统一评测集上验证策略，将稳定能力服务化接回 Agent 平台。

Agent 平台早期采用基础 RAG 支撑海关资料问答，但面对跨地区规则、长文档和专业术语时，逐渐出现召回不准、上下文噪声及复杂问题理解不足。项目将 RAG 作为独立专项，在统一评测集上完成检索链路的系统优化，并将验证稳定的能力服务化接回 Agent 平台。

个人职责

  • 基线与指标：整理问答样本和相关文档标注，固定数据集与参数，建立检索、生成和端到端指标，确保策略可复现、可比较。
  • 链路研发：负责解析切分、向量与关键词召回、融合、重排和上下文组装，围绕命中率、排序质量与答案忠实度逐项验证。
  • 策略评估：设计 Query 改写、HyDE、Multi-Query 实验，评估 Self-RAG、CRAG、Adaptive / Agentic RAG，按效果、时延和复杂度选择集成方案。

难点亮点

  • 结构化切分：对比固定长度、递归、语义与结构化切分，保留章节、表格和条款关系，平衡语义完整性与召回粒度。
  • 混合检索与双重排：Dense + Sparse 兼顾语义与编码、术语精确匹配，以 RRF 融合，再结合轻量重排与 Cross-Encoder 精排前置有效证据。
  • 自适应取舍：简单问题走低成本链路，复杂或证据不足的问题进入扩展、纠错或多轮检索；实验策略经同集验证后再进入集成候选。

个人职责

  • 评测体系与 Baseline：整理典型海关问答样本与相关文档标注，建立检索、生成和端到端指标，固定数据集与参数，保证各轮策略能够在统一口径下比较。
  • 检索链路优化：负责文档解析与切分、向量召回、关键词召回、结果融合、重排及上下文组装等核心链路，围绕命中率、排序质量和答案忠实度逐项验证。
  • Query 理解与复杂问题处理：针对海关术语、地区差异和复合问题，设计意图识别、Query 改写、HyDE 与 Multi-Query 等实验方案，提升用户问题与资料表达不一致时的召回能力。
  • 高级策略评估与集成：在统一评测框架中验证 Self-RAG、CRAG、Adaptive RAG 与 Agentic RAG 等方案，根据效果、延迟和工程复杂度选择适用能力，并通过检索服务接口接入 Agent 平台。

难点亮点

  • 结构化感知切分：针对海关规则文档章节长、表格与条款关联紧密的问题，对比固定长度、递归、语义及结构化切分，兼顾语义完整性与召回粒度，减少关键条件被切断。
  • Dense + Sparse 混合检索：结合向量检索的语义召回与关键词检索对业务编码、地区名称和专业术语的精确匹配能力，并通过 RRF 等方式融合结果，降低单一路径漏召回。
  • 双重排提升精度：在初步召回后结合轻量语义重排与 Cross-Encoder 精排，过滤语义相近但业务条件不匹配的资料，将高相关证据稳定前置。
  • 自适应策略路由：对简单事实问题使用低成本快速链路，对复杂或证据不足的问题进入 Query 扩展、纠错或多轮检索，在效果、时延和成本之间动态取舍。
  • 策略验证与线上口径分离：将 Naive、Advanced、Self-RAG、CRAG、Adaptive 与 Agentic 等能力作为专项评估方案，只有在统一评测集上验证稳定的策略才进入集成候选。

技术关键词Trace · LLM-as-Judge · G-Eval · Faithfulness · HitRate · WCP

针对多 Agent、多版本迭代中人工抽测难以比较效果的问题，统一采集执行 Trace，完成自动评分、问题归因、优化任务生成与同集回归，形成持续优化闭环。

随着 Agent 数量和版本持续增加，人工抽测难以横向比较模型、Prompt、RAG 与 Skill 调整效果。项目建设统一评测与优化平台，标准化采集各 Agent 的执行 Trace，完成自动评分、问题归因、优化任务生成与同集回归，形成“评测 - 诊断 - 优化 - 复测”闭环。

个人职责

  • 评测架构：参与 Prompt、RAG、Skill、Agent 四类评测设计，通过统一 Evaluator 接口与 Registry 管理评测器，支持批量执行和版本对比。
  • Trace 接入：设计标准数据结构，记录问题、回答、检索证据、Skill 路由、工具调用和中间状态，低侵入接入不同 Agent。
  • 优化回归：将低分样本转为包含证据、建议、影响范围和验证方式的优化任务，以固定评测集验证优化前后效果。

难点亮点

  • 稳定评分：基于 G-Eval 概率加权思路，归一化候选评分 token 的概率，结合固定温度与评分规则，减少单次打分波动。
  • 声明级诊断：拆分回答中的独立声明，逐条核验检索证据，输出支持、无依据或矛盾判断，将幻觉定位至具体语句。
  • 分层归因：联合 HitRate、WCP、上下文噪声和 Faithfulness，区分知识缺失、召回不足、排序问题与生成偏差，匹配对应优化动作。

个人职责

  • 评测架构与指标体系：参与 Prompt、RAG、Skill、Agent 四类评测能力设计，建立可量化、可复现的评测口径，并通过统一 Evaluator 接口与 Registry 管理评测器。
  • 统一 Trace 接入：设计标准 Trace 数据结构，记录问题、回答、检索结果、Skill 路由、工具调用与中间状态，使平台能够低侵入接入不同 Agent 应用。
  • 诊断与优化闭环：结合检索、生成和行为指标识别低分样本，将问题转化为包含证据、建议、影响范围和验证方式的优化任务，并使用固定评测集完成优化前后回归。

难点亮点

  • LLM-as-Judge 稳定评分：基于 G-Eval 概率加权思想，对候选评分 token 的概率进行归一化，在固定温度和评分规则下减少直接单次打分的离散波动。
  • Faithfulness 声明级诊断：将回答拆分为独立声明，逐条与检索证据核验并输出 supported、unsupported、contradicted 等判断，使幻觉能够定位到具体语句和证据。
  • RAG 问题分层归因：联合分析 HitRate、WCP、上下文噪声与 Faithfulness，区分知识缺失、召回不足、排序不佳、上下文干扰和生成偏差，为不同问题匹配对应优化动作。
  • 可插拔评测流水线：将评测能力组件化，新增指标只需实现统一接口并注册，无需改动主流程；评测任务支持批量执行、结果汇总和历史版本对比。
